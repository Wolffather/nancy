Следуй общим принципам из **best_practices** плюс этим правилам:

## Сценарии
- Моделируй реалистичное поведение пользователей: последовательность действий, паузы (think time), повторные запросы.
- Сценарий должен включать разогрев (ramp-up) для постепенного увеличения нагрузки.
- Добавляй этап постоянной нагрузки для проверки стабильности.

## Проверки
- Проверяй не только статус-коды, но и время ответа (процентили: 95-й, 99-й).
- Отслеживай процент ошибок (5xx, тайм-ауты).
- Проверяй пропускную способность (RPS) при разных уровнях нагрузки.

## Метрики
- Собирай среднее время ответа.
- Собирай максимальное время ответа.
- Собирай количество успешных и неудачных запросов.

## Инструменты
- Используй Gatling (Java/Scala DSL) или JMeter.
- Параметризуй нагрузку (число пользователей, длительность).
- Генерируй отчёт с графиками.

## Пример структуры (Gatling)
```java
class LoadSimulation extends Simulation {
    HttpProtocolBuilder http = http.baseUrl("http://localhost:8080");
    ScenarioBuilder scn = scenario("Load test")
        .exec(http("Get config").get("/config").check(status().is(200)))
        .pause(2)
        .exec(http("Create booking").post("/booking").body(...).check(status().is(201)));
    setUp(scn.injectOpen(rampUsers(100).during(10)).protocols(http));
}
